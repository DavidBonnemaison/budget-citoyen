# Phase 02.2: Close gap — DATA-02/03/04 (synthetic population + DP guarantee + real shock matrix) - Context

**Gathered:** 2026-05-15
**Status:** Ready for planning

## Phase Boundary

This phase closes the three remaining data gap from Phase 1: the 50K synthetic population file was never generated (CASD access pending), the ε ≤ 1.0 DP proof was never executed, and the shock matrix is a 2.6KB placeholder — not calibrated to real Mésange coefficients. The infrastructure code exists from Phase 1; the gap is execution — producing actual artifacts that the TypeScript engines from Phase 2 can consume, using publicly available data sources while CASD access is pending.

## Implementation Decisions

### Data Source Strategy
- **D-01:** Use INSEE aggregate tables (Enquête Revenus Fiscaux et Sociaux, Recensement) as the data source for synthetic population generation. Re-runnable pipeline — when CASD microdata access is approved, swap the data source and regenerate.
- **D-02:** Keep CopulaGAN synthesizer with SDMetrics quality validation. Accept moderate statistical fidelity (~0.3-0.5 distance) with aggregate data; the pipeline is designed to improve when CASD microdata arrives.
- **D-03:** Abstract the data loading layer into a common tabular interface. Both INSEE aggregates and CASD microdata feed the same preprocess.py → train.py → export.py pipeline. TOKENIZED_PATH becomes one input path among several.
- **D-04:** Full population file load (~50-150KB gzipped JSON) into a new PopulationCache module. O(1) HashMap with typed accessors (getByDecile, getByAgeGroup, getProfileById). Loaded via WorkerOrchestrator INIT, same pattern as ScenarioCache.

### Shock Matrix Calibration
- **D-05:** Hybrid calibration strategy: published IRFs from DG Trésor/Mésange working papers define the dynamic propagation skeleton (shock→response over 5 years). Historical budget elasticities from budget.gouv.fr execution data (2000-2024) scale the IRF magnitudes to French fiscal reality.
- **D-06:** 3D grid structure: tax_rate, spend_level, time_horizon — 12 breakpoints per dimension (~1728 grid points per output variable). Same dimension convention as the existing macro-interpolate.ts engine.
- **D-07:** Point estimate trajectory per grid point. No confidence bands. Methodology page transparently documents calibration sources (working papers, elasticities, limitations). No false precision.

### Differential Privacy Execution
- **D-08:** Execute dp_inject.py as a pipeline property — run `prove_dp_guarantee()` on whichever data source generates the 50K population. The ε ≤ 1.0 proof is valid structurally regardless of data provenance. Re-run when CASD data arrives.
- **D-09:** Preserve existing ε budget allocation: ε/5 per revenu decile, ε/3 per patrimoine age bracket, ε/2 for Gini coefficient. Sequential composition via OpenDP `make_basic_composition()`.
- **D-10:** DP noise applied to aggregates only (population-level statistics in .meta.json). Individual 50K profiles remain unmodified for accurate O(1) micro lookups. Phase 3/4 UI queries aggregate stats for distributional charts — noise there prevents reconstruction.
- **D-11:** Extend .meta.json sidecar with `dp_data_source` and `dp_proof_timestamp`. Export `build_privacy_statement()` (CNIL deliberation n° 2021-122) as machine-readable JSON block for the methodology page.

### Artifact Integration with Engines
- **D-12:** New `PopulationCache` TypeScript class — separate module from the existing `ScenarioCache`. Same O(1) HashMap pattern, loaded via WorkerOrchestrator INIT protocol. No changes to existing ScenarioCache.
- **D-13:** Shock matrix transparent replacement — swap the 2.6KB placeholder with the calibrated matrix. If 3D grid convention and dimension-major obs ordering are preserved, `macro-interpolate.ts` requires zero changes.
- **D-14:** Population file format: JSON (export.py's existing format) with gzip compression and SHA-256 integrity hash. ~50-150KB gzipped for 50K profiles. Matches existing JSON consumption patterns in TypeScript engines.
- **D-15:** New vitest integration tests: `population-cache.test.ts` (loads JSON, validates typed accessors, 50K profile validation) and `shock-matrix-integration.test.ts` (validates calibrated matrix dimensions, interpn returns non-null for grid-center points). Existing tests unchanged.

## Specific Ideas

- The INSEE aggregate data loader should target tables published by Insee Résultats: distribution of revenu fiscal de référence by decile and family type, age pyramid, patrimoine distribution (Enquête Patrimoine), and activity/employment status. Even marginal distributions can feed CopulaGAN copulas.
- For the hybrid IRF + elasticity calibration: use published Mésange IRFs for the dynamic shape (years 1-5 trajectory of GDP/deficit/debt/employment response). Scale each IRF's magnitude using OLS elasticities from budget execution data (2000-2024). Document which working papers and time series were used.
- The common tabular interface should be a simple protocol: a `load(source_type: str)` function that returns a pandas DataFrame with standardized column names. INSEE loader, CASD loader, and fallback generator all implement this same contract.
- The PopulationCache should mirror ScenarioCache's architecture exactly: constructor takes typed docs, exposes `getProfile(id: string): Profile`, `getProfilesByDecile(decile: number): Profile[]`, `getProfilesByAgeGroup(label: string): Profile[]`. Loaded during WorkerOrchestrator.init().
- The shock matrix calibration should preserve the existing 3D grid convention and dimension-major obs ordering that macro-interpolate.ts already handles. No format migration needed — just replace the data.
- DP proof execution should be a single invocation: `prove_dp_guarantee()` returns formal proof, `inject_dp_privacy()` applies noise to aggregates, `build_privacy_statement()` generates the attestation. The .meta.json sidecar captures all three outputs.
- Vitest integration tests should validate both the data contract (correct format, valid profiles, non-null interpolations) AND the performance contract (<1ms lookup, <50ms interpolation). Match existing test patterns from scenario-cache.test.ts.
