<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator.ts → citizen-worker.ts postMessage | Serialized JSON crosses main-thread→worker boundary — structurClone used implicitly by postMessage |
| population-v2025.1.json (string) → JSON.parse in worker | Untrusted JSON deserialization — PopulationCache.fromDoc() is the validation entry point |
| populationJson parameter → orchestrator.init() | String parameter from caller (main thread) — no validation here, caller is responsible for SHA-256 verification before passing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.2-23 | Tampering | populationJson string in transit (orchestrator → worker) | accept | postMessage uses structured clone — the browser runtime guarantees message integrity between same-origin contexts. No network boundary is crossed. |
| T-02.2-24 | Denial of Service | Malformed JSON passed to PopulationCache.fromDoc() | mitigate | PopulationCache.fromDoc() (Plan 05) iterates over profiles array and validates structure. JSON.parse will throw on invalid JSON, which is caught by the citizen-worker's try/catch and returned as ERROR response. Orchestrator's pending.reject handles the ERROR. |
| T-02.2-25 | Information Disclosure | populationJson logged to console | mitigate | No console.log of populationJson payload. The citizen-worker and orchestrator code do not log message payloads — only message types and IDs are used in debug logging. Verify: grep the modified files for `console.log.*populationJson` — should return 0. |
| T-02.2-26 | Elevation of Privilege | init() called multiple times with different populationJson | accept | Each init() call replaces the previous PopulationCache (worker variable reassignment). This is the intended behavior — Phase 3 UI may re-initialize with different population data (e.g., switching reference years). The orchestrator handles the sequential init pattern correctly via Promise resolution. |
</threat_model>
