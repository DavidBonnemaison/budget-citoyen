## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| scenario_definitions.py → precompute.py | Scenario parameter_overrides dict passes from definition (trusted Python source) to extraction block | Dict[str, Any] parameter overrides — no external input |
| precompute.py → scenarios-v2025.1.json | Pre-computed results serialized to JSON file | ScenarioResult × 32 profiles per scenario — must match TypeScript consumer contract |
| local openfisca-france → precompute.py | Python computation runs trusted formulas against trusted fixture data | Tax-benefit calculations — no external input |
| scenarios-v2025.1.json → TypeScript ScenarioCache | JSON consumed by main-thread fetch() or postMessage | Pre-computed scenario results — parse errors caught by try/catch |
| CI scenario-precompute → CI typescript-tests | Same workflow, artifact sharing via checkout; output committed as static asset | scenarios-v2025.1.json — CI job order enforces freshness |
| Vitest test → scenarios-v2025.1.json | Test loads committed JSON file from filesystem | File integrity protected by git hashes |

## Threat Register

| Threat ID | Category | Component | Disposition | Mitigation | Status |
|-----------|----------|-----------|-------------|------------|--------|
| T-02.1-01 | Tampering | scenarios-v2025.1.json output | mitigate | JSON Schema (Draft 2020-12) validates output structure, field types, value ranges, and required fields via `jsonschema` in CI step before TypeScript tests consume the output (`.github/workflows/phase2-wasm.yml:207-228`) | closed |
| T-02.1-02 | Repudiation | openfisca-france version tracking | mitigate | `openfisca_france_version` recorded in output metadata field (`precompute.py:592`); CI version gate warns on out-of-range versions; exact version traceable in every generated artifact | closed |
| T-02.1-03 | Tampering | Bilingual test fixtures | accept | Fixtures committed to git with review; pre-compute results cross-validated against fixture expected values; source of truth is the openfisca-france Python reference — no external untrusted input | closed |
| T-02.1-04 | Tampering | Scenario parameter overrides injection | accept | `parameter_overrides` are hardcoded as inline dict literals in Python source (`scenario_definitions.py:122-497`) — no user input reaches the pipeline at runtime; modifications require code review on PR | closed |
| T-02.1-05 | Tampering | Pipeline output between CI jobs | mitigate | `typescript-tests` job `needs: [scenario-precompute]` in same workflow (`.github/workflows/phase2-wasm.yml:243-246`); output file committed to repo as static asset with git integrity | closed |
| T-02.1-06 | Tampering | Test assertion bypass | mitigate | Python tests use `==` for exact numeric comparisons (`test_scenario_precompute.py:169,184,243`); TypeScript integration test uses `===` and `.toBe()` strict matchers (`scenario-cache-integration.test.ts:49,89,126`) — no `toBeCloseTo()` or approximate matchers used | closed |
| T-02.1-07 | Tampering | Skipped tests masking failures | mitigate | TypeScript integration test catches `ENOENT` via try/catch in `loadDocs()` and returns early when JSON not available (`scenario-cache-integration.test.ts:19-37`); Python `test_validate_scenarios_output` does `return` (not `skip`) when output file missing (`test_schema_validation.py:73-74`); tests fail in CI where JSON is always generated by scenario-precompute job | closed |
| T-02.1-08 | Tampering | Schema validation bypass | mitigate | Schema validation step ("Validate scenarios JSON Schema") runs inside the `scenario-precompute` CI job (`.github/workflows/phase2-wasm.yml:207-228`), not as a separate skippable job; both count gate AND schema validation must pass before job succeeds | closed |

*Status: open · closed*
*Disposition: mitigate (implementation required) · accept (documented risk) · transfer (third-party)*
