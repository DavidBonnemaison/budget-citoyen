## Nyquist Gap Resolution Results

### MICRO-01: IR non-negative — FILLED

- **Command:** `npx vitest run src/engine/__tests__/scenario-cache-integration.test.ts`

### MICRO-03: Aides match bilingual fixtures — ESCALATED (BLOCKER)
- **Test:** Added `test_aides_match_bilingual_fixture_expected_values` to `TestPrecomputePipeline`
- **Command:** `.venv/bin/python -m pytest tests/test_scenario_precompute.py::TestPrecomputePipeline::test_aides_match_bilingual_fixture_expected_values -v`
- **Result:** 3/32 profiles fail — aides mismatch for non-salaried income types
- **Root cause:** Simplified `_estimate_aides()` in `precompute.py` (lines 262-269) uses `revenu_brut_global` for RSA eligibility threshold check (`revenu_brut < rsa_personne_seule * 1.2`). The openfisca-france reference simulator applies different resource definitions per income type:
  - **Profile 25 (agriculteur_zone3):** bénéfice agricole receives specific cotisations MSA deductions → different RSA resource base. Expected RSA=7628.52, computed=0.
  - **Profile 26 (auto_entrepreneur):** micro_bic has 50% abattement applied to RSA resource calculation. Expected RSA=7628.52, computed=0.
  - **Profile 27 (handicape_aah):** AAH is excluded from RSA resource calculation. Expected RSA=7628.52, computed=0.
- **Required fix:** Extend `_estimate_aides()` RSA calculation to apply income-type-specific resource definitions (agricultural abattement, micro-BIC abattement, AAH exclusion) or re-scope requirement to exclude these profile types.
- **Implementation file:** `packages/data-pipeline/src/scenarios/precompute.py` — `_estimate_aides()`
- **Status:** ❌ red

### MICRO-05: Lookup performance < 1ms — FILLED
- **Test:** Added `lookup() performance` describe block to `scenario-cache.test.ts`
