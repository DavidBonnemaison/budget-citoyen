# Phase 02.1: Close Gap — Architecture Resolution + Precompute Execution - Context

**Gathered:** 2026-05-14
**Status:** Ready for planning

## Phase Boundary

This phase delivers the actual execution of the Python scenario pre-compute pipeline — taking the existing infrastructure (scenario_definitions.py, precompute.py) and producing the `scenarios-v2025.1.json` file that the TypeScript ScenarioCache consumes for O(1) citizen-mode lookups. It resolves the remaining architecture gaps from the Phase 2 hybrid transition: executing the pipeline end-to-end, expanding from 3 to 12 scenarios, formalizing the JSON-contract validation, and installing the openfisca-france runtime dependency locally.

The TypeScript engine (ScenarioCache, macro-interpolate, workers, orchestrator) already exists and is tested — it just needs real data. The webapp scaffold (Vite/React/TS/Tailwind) was created by Phase 3 Plan 03-01 and is ready to consume the output.

## Implementation Decisions

### Scenario Scope

- **D-01:** 12 scenarios total: 1 baseline (droit en vigueur 2025) + 5 political programs (LFI/NFP, Renaissance, LR, RN, Gauche sociale-démocrate/PS) + 3 pedagogical scenarios (Financement de la transition écologique, Revenu universel, Retour à l'équilibre budgétaire) + 3 single-axis variants (IR seul, TVA seule, Dépenses publiques seules). The 3 variants fill the interpolation space around the 4 citizen levers.
- **D-02:** Political programs should reflect publicly known 2027 proposals where possible — parameter overrides aligned with each current's documented fiscal platform. Pedagogical scenarios are exploratory, illustrating extreme or novel fiscal configurations.
- **D-03:** Pre-compute runs on the 32 canonical profiles from `bilingual_test_fixtures.json` (not the full 50K synthetic population). Phase 4 handles the full distributional analysis. The 32 profiles cover the 3 citizen-facing display profiles (bas revenu ~14K€, médian ~26K€, aisé ~60K€).

### IS and TVA Model Fidelity

- **D-04:** IS contribution remains `0.0` in the micro pre-compute (per-profile). Individual profiles lack enterprise data — IS is not a household tax. IS reform impacts are modeled through the macro engine only (ShockMatrix `tax` axis), affecting deficit/debt/GDP/employment projections but not per-household disposable income. This is the correct semantic for a citizen-facing simulator.
- **D-05:** TVA retains the simplified consumption model in `precompute.py`: 70% of disposable income consumed, 60% at standard rate, 25% at reduced rate (5.5%), 15% exempt. Effective rate ~13-15% of disposable income. TVA rate changes also flow through the macro ShockMatrix `tax` axis for economy-wide projections.

### Execution Strategy

- **D-06:** openfisca-france must be installed in the local development environment (`pip install openfisca-france>=159,<200`). The pipeline runs locally for development iteration and validation, then runs in CI as a gating job. The lazy-import pattern in `scenario_definitions.py` is preserved so the package remains importable without openfisca-france at import time.
- **D-07:** Pipeline output: `packages/data-pipeline/dist/scenarios-v2025.1.json` — a single JSON file containing all 12 `ScenarioDoc` entries + metadata block (`version`, `reference_year`, `generated_at`, `openfisca_france_version`, `total_scenarios`, `total_profiles`). This file is committed to the repo as a static asset (compressed size estimated ~50-100KB for 12 × 32 profiles).

### Contract Validation

- **D-08:** Dual validation: (1) JSON Schema (Draft 2020-12) defined for the output document format, validated in CI via Python `jsonschema` after pipeline execution. (2) TypeScript integration test using Vitest that loads the produced JSON through `ScenarioCache.fromDocs()` and verifies `lookup()` returns valid `ScenarioResult` objects for all scenario × profile combinations. Both validations run in CI as gating checks.

## Existing Code Insights

### Reusable Assets
- `precompute.py`: Complete pre-compute pipeline that loads profiles, applies scenario overrides, computes simplified formulas, and exports JSON. Only needs scenario definitions expanded and openfisca-france installed.
- `scenario_definitions.py`: ScenarioDefinition dataclass + 3 existing scenarios as patterns. Expand by adding more entries to `get_scenario_definitions()`.
- `ScenarioCache` + types: Fully implemented and tested. `ScenarioCache.fromDocs()` is the primary entry point. `ScenarioCache.loadFromJSON()` for main-thread fetch.
- `macro-interpolate.ts`: Pure TS trilinear interpolation — no changes needed.
- `WorkerOrchestrator`: Worker coordination with correlation IDs — no changes needed.

### Established Patterns
- Version-locking: all artifacts tagged `-v2025.1`. Output file follows: `scenarios-v2025.1.json`.
- Lazy imports: openfisca-france imported inside functions, not at module level. Preserve this.
- Simplified formulas: hand-rolled Python using openfisca-france parameters, cross-validated against bilingual test fixtures. No full entity/period simulation.
- ScenarioDefinition.build_reform() pattern: Reform subclass with `apply()` that calls `self.modify_parameters()`. Copy this pattern for new scenarios.
- JSON key convention: profile indices stored as string keys (`"0"`, `"1"`, ...) because JSON cannot represent numeric keys. TypeScript `ScenarioCache.addScenario()` converts back via `Number(key)`.

### Integration Points
- `precompute.py` → `scenarios-v2025.1.json` → `ScenarioCache.loadFromJSON(url)` (main thread fetch)
- `ScenarioCache.fromDocs(docs)` → `citizen-worker.ts` (via postMessage during INIT)
- `scenario-precompute` CI job → validates JSON output → `typescript-tests` CI job consumes it

### Deprecatable Code
- None — all existing code is preserved. This phase is additive (expand scenarios, validate contract).

## Specific Ideas

- The 5 political programs should use parameter overrides that match each party's publicly stated fiscal platform as of early 2026. Each scenario's `description` should summarize the key fiscal measures in 2-3 sentences.
- The 3 pedagogical scenarios can be more creative: "Transition écologique" could combine a carbon tax with green investment credits; "Revenu universel" could replace RSA + prime d'activité with a flat transfer; "Équilibre budgétaire" could combine across-the-board tax increases with spending cuts.
- The 3 single-axis variants should use symmetric ± values around baseline (e.g., IR ±15%, TVA ±3pts, Dépenses ±10%) to create a balanced interpolation grid.
- The JSON Schema should validate at minimum: top-level `scenarios` array, each entry has `definition` + `results`, `definition` has `id`/`name`/`description`/`parameterOverrides`, `results` values have `ir`/`is`/`tva`/`cotisations`/`aides`/`revenuDisponible`.
- The Vitest integration test should load the committed `scenarios-v2025.1.json` from `../packages/data-pipeline/dist/` (relative to webapp) and verify ScenarioCache.fromDocs() constructs successfully, then spot-check a few lookups.
