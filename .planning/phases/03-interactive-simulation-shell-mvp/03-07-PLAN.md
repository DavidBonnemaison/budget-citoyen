**useSimulation.ts — Central simulation hook (D-07, D-15, D-23):**

Following RESEARCH.md Architecture diagram and PATTERNS.md lines 260-306:

State management:
- `phase`: 'loading' | 'preselect' | 'displaying' | 'error'
- `orchestratorRef`: useRef<WorkerOrchestrator | null> — created once
- `scenarioCacheRef`: useRef<ScenarioCache | null> — reference to cache for interpolation queries. The cache lives in the citizen worker; the main thread needs a lightweight copy of ScenarioDefinitions for interpolation (RESEARCH.md Open Q3 — use INTERPOLATE message type to citizen worker, OR maintain cache copy on main thread)
  - IMPLEMENTATION DECISION: For Phase 3 MVP, ScenarioCache is available on the main thread via ScenarioCache.loadFromJSON(). The interpolation layer (interpolateScenarios) calls cache.lookup() directly. The citizen worker is used for initial data loading but interpolation runs on main thread for simplicity (RESEARCH.md OQ3 recommendation: add INTERPOLATE to citizen worker, but for MVP, main-thread interpolation with ScenarioCache reference is simpler and still <1ms)
- `scenarios`: ScenarioDefinition[] — loaded from ScenarioCache after init
- `selectedScenarioId`: string | null
- `sliderState`: SliderState (default all zeros)
- `microResults`: (ScenarioResult | null)[] — array of 3, one per profile
- `macroResult`: MacroResult | null
- `isComputing`: boolean — for opacity pulse on charts
- `errorMessage`: string | null
- `loadProgress`: { phase: string; percent: number }
- `advancedMode`: boolean

Key methods:
1. **init():** Called from App on mount.
   - setPhase('loading'), update loadProgress with phases: "Récupération des données…" (0-50%) → "Initialisation du moteur de simulation…" (50-100%)
   - Per RESEARCH.md Pitfall 1: fetch scenarios JSON → await .text() / fetch shock matrix → await .arrayBuffer(), then orchestrator.init(scenariosJson, matrixBytes)
   - After init resolves: build ScenarioCache from scenarios JSON (ScenarioCache.loadFromJSON or fromDocs), populate scenarios state
   - Check URL for ?state= param — if present, decode and pre-load
   - setPhase('preselect')
   - On error: setPhase('error'), set error message

2. **selectScenario(id):**
   - setPhase('displaying'), setSelectedScenarioId(id)
   - Call orchestrator.simulate(id, 0/1/2) in parallel for 3 profiles
   - Set microResults with 3 ScenarioResults
   - Auto-position sliders: read scenario's parameterOverrides, set sliderState accordingly (convert from parameter values to % changes using index-map)
   - Call orchestrator.project(tax, spend, 5) for initial macro result

3. **handleSliderChange(key, value):**
   - Update sliderState[key] = value (synchronous — instant label)
   - Call interpolation: interpolateScenarios(sliderState, scenarios, scenarioCache, profileIndex) for each profile
   - Update microResults with blended results
   - WorkerOrchestrator's stale response discarding handles rapid-fire requests — no manual throttling needed (D-15)

4. **handleDragEnd(key, value):**
   - Same as handleSliderChange + trigger orchestrator.project() for macro update
   - startTransition(() => setIsComputing(true)) per Pitfall 3
   - orchestrator.project().then(result => { setMacroResult(result); setIsComputing(false); })

5. **handleReset():** Per D-14 — set sliderState to all zeros, set selectedScenarioId null, clear microResults and macroResult, setPhase('preselect')
6. **retry():** Re-run init()
7. **toggleAdvanced():** Toggle advancedMode boolean

URL state integration (D-23):
- On mount: read `new URLSearchParams(window.location.search).get('state')`, decode via decodeState(), restore scenario/sliders/profile/advanced
- On scenario select and drag-end: call pushState() with current URLState
