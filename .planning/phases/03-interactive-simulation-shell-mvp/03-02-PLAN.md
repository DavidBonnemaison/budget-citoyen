  ### Module 2: url-codec.ts — URL State Encoding/Decoding (D-23)
  Three pure functions implementing Pattern 5 from RESEARCH.md (lines 433-459):

  **encodeState(state: URLState): string**
  - JSON.stringify → btoa(unescape(encodeURIComponent(json))) as per RESEARCH.md Pitfall 4
  - Returns base64 string suitable for ?state= query parameter

  **decodeState(encoded: string): URLState | null**
  - Reverse: atob → decodeURIComponent → JSON.parse
  - Type-check after parse: s must be string|null, f must be number, a must be boolean, p must be object with 5 numeric fields
  - Return null for any parse failure or type mismatch (never throw)
  - Per threat T-03-03 (URL state injection): ignore unknown fields, validate scalar types

  **pushState(state: URLState): void**
  - Constructs URL with encodeState, calls window.history.replaceState
  - No return value

  Test cases for url-codec.test.ts:
  - encodeState produces a valid base64 string
  - decodeState returns null for "!!!not-valid!!!"
  - decodeState returns null for valid base64 that doesn't match URLState shape (missing f field)
  - decodeState(encodeState(original)) round-trips correctly for full state with all 5 sliders non-zero
  - decodeState handles scenarioId=null (s: null in state) correctly
  - encodeState handles special characters: slider values like ±, scenario names with é/è/ù

  ### Module 3: interpolation.ts — Scenario-to-Scenario Interpolation (D-01, D-02)
  Implement the inverse distance weighting algorithm from RESEARCH.md Pattern 3 (lines 323-381):

  **interpolateScenarios(sliderParams: SliderState, scenarioDefs: ScenarioDefinition[], scenarioCache: ScenarioCache, profileIndex: number, k: number = DEFAULT_K): InterpolationResult | null**

  Algorithm:
  1. Guard: return null if scenarioDefs empty, profileIndex < 0, or k < 1
  2. Compute Euclidean distance in parameter space for each scenario (sum of squared diffs across all 5 sliders)
  3. Sort by distance ascending, take top k
  4. If nearest distance < EXACT_MATCH_THRESHOLD (1e-3), return exact match with isExact=true
  5. Inverse distance weighting: w_i = (1/d_i) / Σ(1/d_j)
  6. Weighted blend of ScenarioResults: for each field (ir, is, tva, cotisations, aides, revenuDisponible), compute sum(result_i[field] * weight_i)
  7. Return InterpolationResult with blended scenarioResult, source scenario IDs, weights, isExact=false

  Per CONTEXT.md D-02: each tax slider interpolates independently. The distance metric computes across all 5 dimensions automatically.

  Module-level constants: DEFAULT_K = 3, EXACT_MATCH_THRESHOLD = 1e-3.

  Test cases for interpolation.test.ts (requires a helper `makeTestCache()` to build a ScenarioCache with 3-5 synthetic scenarios):
  - Returns exact match when slider positions exactly match a scenario (distance < threshold)
  - Returns weighted blend for between-scenario positions with weights summing to 1.0 (toBeCloseTo)
  - Returns null for empty scenario list
  - Returns null for negative profileIndex
  - k=1 returns the single nearest scenario (not a blend)
  - Correctly weights: closer scenario gets higher weight than farther scenario
  - All ScenarioResult fields are blended correctly (verify one field matches expected weighted sum)
  - isExact is false for blended result, true for exact match

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query param → decodeState() | Untrusted base64 string from `?state=` parameter crosses into application state |
| Slider values → interpolation | User-provided numeric values enter the interpolation algorithm |
| ScenarioCache.lookup() results → blended ScenarioResult | Data from pre-computed cache enters the weighted blend computation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Tampering | url-codec.ts — URL state injection via malformed base64 | mitigate | decodeState() implements strict type validation after parse: `s` must be string\|null, `f` must be number, `a` must be boolean, `p` must be object with exactly 5 numeric fields (ir, is, tva, cotisations, depenses). Unknown fields are ignored. Malformed base64 (invalid characters, truncated, non-JSON) returns null — never throws. Caller treats null as "no saved state" and falls back to defaults |
| T-03-04 | Tampering | interpolation.ts — data poisoning via crafted slider values | mitigate | interpolateScenarios() guards: returns null for empty scenarioDefs, negative profileIndex, or k < 1. Slider values are bounded by LeverSlider's min/max/step constraints (React Aria enforces). Euclidean distance naturally bounds influence — values far outside the parameter space produce large distances, giving them near-zero weight in the inverse-distance blend. Exact match threshold (1e-3) prevents precision attacks |
| T-03-05 | Information Disclosure | index-map.ts — lever mapping proportions exposed | accept | LEVER_MAPPINGS is a public constant defining which sub-parameters each citizen lever controls. No secrets or PII — this is the "how the simulator works" transparency that the methodology page explains. Acceptable for open-source citizen tool |
| T-03-06 | Denial of Service | interpolation.ts — large scenario sets or extreme k values | mitigate | interpolateScenarios sorts by distance and takes only top-k (default k=3). Full sort complexity is O(n log n) where n ≤ 12 scenarios (D-03). Even with extreme k=12 it's trivial. No amplification vector exists |
</threat_model>
