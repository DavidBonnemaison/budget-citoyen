From RESEARCH.md Pattern 3 (lines 480-525) — the Profile struct contract:

The Profile struct is the flat representation (D-13) of an OpenFisca household. All cross-entity references (Individu, Famille, FoyerFiscal, Menage) are resolved by the code generator, which adds fields beyond the initial hand-written ones. The initial struct includes the core fields needed by all tax calculations.

**Required Profile fields (hand-written, extended by codegen per D-15):**
- profile_id: String — unique identifier from synthetic population
- age: u8 — principal declarant age (0-120)
- patrimoine: f64 — total wealth (immobilier + financier, >= 0)
- revenu_fiscal: f64 — fiscal reference income (>= 0)
- situation_familiale: SituationFamiliale — celibataire, marie, pacse, veuf, divorce
- nombre_parts: f64 — quotient familial parts (>= 1.0, typically 1.0-5.0)
- type_activite: TypeActivite — salarie, independant, retraite, chomeur, inactif
- nb_enfants: u8 — number of dependent children (0-20)

**Required enums:**
- SituationFamiliale: Celibataire, Marie, Pacse, Veuf, Divorce
- TypeActivite: Salarie, Independant, Retraite, Chomeur, Inactif

**Required LoadError variants (D-16):**
- InvalidAge(u8) — age > 120
- NegativeWealth(f64) — patrimoine < 0.0
- NegativeIncome(f64) — revenu_fiscal < 0.0
- InvalidParts(f64) — nombre_parts < 1.0
- MissingField(String) — required field not present in deserialization

**Required output types (D-10, from RESEARCH.md lines 505-525):**
- MicroResult: { ir: f64, is_contribution: f64, tva_acquittee: f64, cotisations_salariales: f64, csg_crds: f64, aides: AidesResult, revenu_disponible: f64 }
- AidesResult: { rsa: f64, apl: f64, allocations_familiales: f64, prime_activite: f64, aah: f64, aspa: f64, total: f64 }
- MacroResult: { deficit_trajectory: Vec<f64>, debt_trajectory: Vec<f64>, gdp_growth_trajectory: Vec<f64>, employment_trajectory: Vec<f64>, is_out_of_bounds: bool, warning_message: Option<String> }
