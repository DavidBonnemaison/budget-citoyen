**TaxBenefitSystem API (from PATTERNS.md lines 357-384):**
```rust
pub struct TaxBenefitSystem {
    parameters: Parameters,
    profiles: Vec<Profile>,
}

impl TaxBenefitSystem {
    pub fn new(parameters: Parameters, profiles: Vec<Profile>) -> Self;
    pub fn compute_all_taxes(&self, profile_index: usize) -> MicroResult;
}
```
compute_all_taxes() calls all generated formula functions for the profile at the given index. The generated functions follow the naming convention: `calculate_ir_bareme`, `calculate_tva_acquittee`, `calculate_rsa`, etc.

**SimulationState pattern (D-09, from PATTERNS.md lines 387-410):**
```rust
pub const NUM_SIMULATION_PARAMS: usize = 16;

pub struct SimulationState {
    params: [f64; NUM_SIMULATION_PARAMS],
    // ... cached computed values (optional)
}

impl SimulationState {
    pub fn update_params(&mut self, input: &[f64]) -> Result<(), &'static str>;
    pub fn compute_for_profile(&self, system: &TaxBenefitSystem, profile_index: usize) -> MicroResult;
}
```

**Index mapping (D-09, from RESEARCH.md lines 332-348):**
```
Index 0-4  : IR bracket rates (5 brackets)
Index 5    : IS rate
Index 6-7  : TVA normal / TVA reduced rate
Index 8-9  : CSG deductible / CRDS rate
Index 10-11: Cotisations salariales / patronales
Index 12   : Dépenses publiques level
Index 13   : Effectifs État factor
```
(16 total for v1 — remaining 2 indices reserved for Phase 3/4 extensions)

**Precision threshold (D-13, ROADMAP.md success criterion 1):**
1e-6 relative precision. Comparison formula: `|rust_value - python_value| < 1e-6 * max(|python_value|, 1.0)`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase 1 dist/ bilingual_test_fixtures.json → FixtureDoc deserialization | Bilingual validation fixtures deserialized at compile time via include_str! — fixture integrity verified by Phase 1 SHA-256 hash. |
| TaxBenefitSystem::compute_all_taxes → generated formula functions | Formula dispatch boundary between hand-written system.rs and auto-generated Rust code from Plan 02-04. |
| Fixture Profile → TaxBenefitSystem computation → MicroResult | Full computation chain: fixture input → Profile → ~200+ formula calls → MicroResult. Precision drift can accumulate across formula chains. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-34 | Tampering | profile_index out-of-bounds in compute_all_taxes | mitigate | Bounds-check `profile_index < self.profiles.len()` at entry to compute_all_taxes. Return `Err("Profile index out of bounds")` — never panic with index access. |
| T-02-35 | Tampering | Generated code with unsafe blocks or runtime panics | mitigate | CI gate: `grep -r "unsafe" packages/wasm-micro/src/generated/` MUST return 0 matches (cross-ref T-02-09 from Plan 02-04). Generated formulas are pure functions with no allocation, no unwrap(), no recursion. Compute_all_taxes wraps each formula call to catch panics if codegen produces unexpected code paths. |
| T-02-36 | Information Disclosure | Error messages leaking internal tax computation state | mitigate | Error messages describe failure type only (e.g., "Parameter key not found: ir.bareme", "Profile index X out of bounds (max Y)"). Never expose intermediate computed values, full Profile data, or internal formula dispatch state. French-language messages per project convention. |
| T-02-37 | Tampering | Bilingual fixture JSON tampered to always pass (validation bypass) | mitigate | Fixtures generated by Phase 1 pipeline (`export_fixtures.py`) with SHA-256 integrity hash verified at CI time (Plan 02-01 Task 2). Fixtures are embedded at compile time via `include_str!` — runtime cannot swap fixtures. CI version-check gate (Plan 02-08) verifies fixture file hash matches Phase 1 export. |
| T-02-38 | Denial of Service | Precision drift accumulation across ~200+ formula chains | mitigate | Bilingual validation tests compare MicroResult fields against OpenFisca Python reference at ≤1e-6 precision for all 32 canonical profiles. Each formula function returns f64 — no cumulative error state. If any profile exceeds precision threshold, test fails and blocks merge. CI runs bilingual suite on every push (Plan 02-08 `cargo-test-core` job). |
</threat_model>
