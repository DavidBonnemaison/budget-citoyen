<objective>
Create the WASM boundary layer for both engine crates — the thin `#[wasm_bindgen]` wrapper that exposes Rust computation to JavaScript. Per D-09 and D-10, inputs cross the boundary as flat `&[f64]` slices (zero serialization), outputs return as typed `JsValue` objects via `serde-wasm-bindgen`. This plan also adds `wasm-bindgen-test` browser-context tests to verify the JS↔WASM round-trip works correctly.

Purpose: The WASM boundary is the contract between Rust computation and JavaScript consumers. Without it, the engines cannot run in the browser. The boundary MUST be thin — all business logic stays in the module files created by earlier plans.

Output: Working WASM exports for both engines, passing wasm-pack test suite in browser context, and verified `wasm-pack build` output.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JS caller → WASM (MicroEngine::update_and_simulate) | Untrusted input: &[f64] slice from JavaScript slider values. Must validate length and bounds. |
| JS caller → WASM (MacroEngine::interpolate) | Untrusted input: f64 values from JavaScript. Must validate convex hull containment. |
| JS caller → WASM (constructor) | Untrusted JSON strings for parameters and population. Must validate via serde deserialization. |
| WASM → JS console (panic hook) | WASM panic must NOT dump linear memory contents to browser console (ASVS V7). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | MicroEngine::update_and_simulate | mitigate | Validate params.len() == NUM_SIMULATION_PARAMS (16). Validate profile_index < profiles.len(). Return Err(JsValue) on bounds violation — never panic. |
| T-02-12 | Tampering | MicroEngine::new (JSON deserialization) | mitigate | serde deserialization with strict type checking. Profile::validate() called on every profile per D-16. Malformed JSON returns Err(JsValue). |
| T-02-13 | Information Disclosure | WASM panic hook | mitigate | debug_assertions only: `console_error_panic_hook::set_once()`. Production builds: `std::panic::set_hook(Box::new(|_| {}))` — suppress all panic output. NEVER dump memory contents. |
| T-02-14 | Denial of Service | MacroEngine::interpolate with NaN/Infinity | mitigate | Validate inputs: `tax.is_finite() && spend.is_finite() && horizon.is_finite()` before calling interpn. NaN/Infinity enter hull check → doesn't match any hyperplane → returns JsValue::NULL. |
| T-02-15 | Information Disclosure | wasm-pack build output | mitigate | `[profile.release]` with `debug = false` in workspace Cargo.toml. Verify pkg/ contains no `.map` files, no local filesystem paths. Grep pkg/ for "/Users/" — must return 0. |
| T-02-16 | Elevation of Privilege | wasm-bindgen auto-generated JS | accept | wasm-bindgen generates trusted glue code that calls WASM exports directly. No user input is evaluated as code. Risk accepted as standard WASM practice. |
</threat_model>
