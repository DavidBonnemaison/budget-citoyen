Build the automated code generator that translates OpenFisca-France's ~200+ Python tax formulas into Rust source files. Purpose: The code generator is the single most important tool built in this phase. Manual porting of ~200+ formulas would be error-prone and unreproducible. Automated generation ensures consistency, reproducibility, and maintainability as OpenFisca-France updates.

Output: Working Python codegen script, spike-validated approach, generated Rust source files across 5 tax domains that compile cleanly.

**Code generator architecture (per D-05, D-08, RESEARCH.md Pattern 4):**

The code generator lives in `packages/data-pipeline/src/codegen/` (reuses existing Phase 1 venv with openfisca-france >=159,<200).

**Discovery flow:**
1. Instantiate `FranceTaxBenefitSystem()` from openfisca-france
2. Access `.variables` dict — contains all ~200+ variable definitions
3. Build dependency graph (DAG) from each variable's `formulas`, `inputs`, and `dependencies`
4. Topological sort the DAG so formulas are emitted in correct dependency order

**Emitted Rust structure per formula (D-08):**
```rust
// AUTO-GENERATED by codegen. DO NOT EDIT.
// Source: openfisca-france v{OPENFISCA_VERSION}
// Generated: {ISO_TIMESTAMP}

use budget_citoyen_core::types::{Profile, Parameters};
use chrono::NaiveDate;

/// {variable_documentation_from_openfisca}
pub fn calculate_ir_bareme(
    parameters: &Parameters,
    period: NaiveDate,
    profile: &Profile,
) -> f64 {
    // Translated formula body
    // Pattern: typed inputs, pure function, match on period if temporal
}
```

**Tax domain grouping (D-08):**
| Domain | openfisca-france prefix filter | Output file |
|--------|-------------------------------|-------------|
| IR | variables starting with "ir_" or "impot_revenu" | generated/ir.rs |
| IS | "is_" or "impot_societes" | generated/is.rs |
| TVA | "tva_" | generated/tva.rs |
| Cotisations | "csg_", "crds_", "cotisations_", "forfait_social_" | generated/cotisations.rs |
| Aides | "rsa_", "apl_", "allocations_", "prime_activite_", "aah_", "aspa_", "paje_", "are_" | generated/aides.rs |

**Flat Profile struct extension (D-13, D-15):**
The codegen also emits a `ProfileExtension` struct containing all leaf input variables discovered during introspection. These fields are added to the hand-written Profile struct. The codegen writes this to `packages/wasm-micro/src/generated/profile_fields.rs`.

**Formula translation rules:**
- OpenFisca's `parameters(period).barème` → `parameters.get_brackets("ir.bareme")`
- OpenFisca's `simulation.calculate('revenu_disponible', period)` → `calculate_revenu_disponible(parameters, period, profile)`
- OpenFisca's entity access (`individu.salaire`) → `profile.salaire` (flat struct per D-13)
- Python `if/elif/else` → Rust `if/else if/else` (equivalent)
- Python `sum()` → Rust `.iter().sum()`
- Python `max()`, `min()` → Rust `f64::max()`, `f64::min()`
- Unsupported patterns: emit `// TODO: MANUAL_PORT` comment with original Python source

**Spike approach (RESEARCH.md Open Question #2):**
Before generating the full tree, spike 3-5 representative formulas:
1. **Simple scalar**: TVA taux normal application (accesses `parameters.get_scalar("tva.taux.normal")`, multiplies by consumption estimate)
2. **Brackets with threshold**: IR barème progressif (iterates brackets, applies marginal rates with quotient familial)
3. **Cross-entity reference**: RSA eligibility (depends on foyer fiscal revenus AND famille composition)
4. **Conditional computation**: Décote IR (if revenu_fiscal < threshold × parts then apply reduction)
5. **Aide with multiple conditions**: APL (depends on revenu, zone_residence, situation_familiale, loyer)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | generate_rust.py output | mitigate | Generated files contain AUTO-GENERATED header with source version and timestamp. Any manual edits would be overwritten on re-run. Codegen is deterministic (same input → same output). |
