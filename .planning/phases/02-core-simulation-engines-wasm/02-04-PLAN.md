<objective>
Define the scenario data format and build the Python CI pipeline that pre-computes citizen-mode microsimulation results. Per CONTEXT.md D-05 (NEW), no formulas are ported to Rust. Instead, this plan produces static scenario lookup data: Python openfisca-france computes results for canonical profiles under each candidate reform scenario, and the results are exported as a versioned, compressed JSON file loaded by the browser.

Purpose: The scenario pipeline is the replacement for formula codegen. It shifts computation from the browser to CI — citizens get instant pre-computed results (zero data transfer), experts use backend Python compute (Phase 5). This satisfies MICRO-01, MICRO-02, MICRO-03 via validated pre-computation rather than client-side WASM formulas.

Output: 3+ candidate scenario definitions, a working precompute pipeline, initial `scenarios-v2025.1.json` file, and Rust types for scenario data deserialization.
</objective>

**Scenario data format (per D-22 — planner/researcher discretion, key constraint: <200ms load+lookup):**

The chosen format is **compressed JSON** — gzip at HTTP level (Content-Encoding). Rationale:
- 32 canonical profiles × 3+ scenarios × ~10 output fields × 8 bytes ≈ 8 KB uncompressed → <2 KB compressed
- JSON is human-auditable (matches project's "audit by non-programmers" value)
- No binary format dependency needed in WASM (keeps wasm-micro binary small)
- Simple serde Deserialize in Rust — no parquet2 dependency
- Well under the 500 KB budget even with 20 scenarios and 100 profiles

**Scenario data JSON schema:**
```json
{
  "version": "scenarios-v2025.1",
  "reference_year": 2025,
  "openfisca_version": "159.1.2",
  "generated_at": "2026-05-13T...",
  "scenarios": [
    {
      "id": "status-quo-2025",
      "name": "Statu quo 2025",
      "description": "Paramètres fiscaux inchangés (référence PLF 2025)",
      "parameters": {
        "ir_bareme_rates": [0.0, 0.11, 0.30, 0.41, 0.45],
        "tva_normal": 0.20,
        "tva_reduit": 0.055,
        "is_rate": 0.25,
        "csg_deductible": 0.068,
        "crds": 0.005,
        "cotisations_salariales_rate": 0.22,
        "cotisations_patronales_rate": 0.42,
        "rsa_montant": 635.71,
        "apl_params": "reference"
      },
      "results": {
        "celibataire_smic": {
          "ir": 0.0,
          "is_contribution": 0.0,
          "tva_acquittee": 1234.56,
          "cotisations_salariales": 4136.22,
          "csg_crds": 1729.69,
          "aides": { "rsa": 0.0, "apl": 150.0, "allocations_familiales": 0.0, "prime_activite": 240.0, "aah": 0.0, "aspa": 0.0, "total": 390.0 },

```

**Canonical profile mapping:** The `results` keys match Phase 1 canonical profile IDs from `bilingual_test_fixtures.json`. The precompute pipeline iterates the same 32 canonical profiles used for bilingual validation.

    pub description: String,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI → CI pipeline (openfisca-france) | Python dependency download during CI — version pinning in pyproject.toml, lockfile integrity |
| openfisca-france computation → scenarios-v2025.1.json | Pre-computed results exported to static file — must be deterministic and auditable |
| CI pipeline → committed repo | Generated scenario data committed to git (D-07) — reviewer must be able to audit results |
| Phase 1 venv → scenario precompute | openfisca-france from Phase 1 venv used for computation — version must match pinned constraint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | precompute.py output (scenarios-v2025.1.json) | mitigate | Output file contains version tag, reference year, openfisca version, and generation timestamp in header. CI version-consistency gate verifies these match pyproject.toml. Deterministic: same input → same output (openfisca-france is deterministic). |
| T-02-07 | Information Disclosure | Scenario data (public fiscal projections) | accept | Scenario data contains only aggregate fiscal projections for canonical (synthetic) profiles. No real person data. All data is already public (tax rates, reform proposals). Risk accepted — scenario data is designed to be publicly auditable. |
| T-02-08 | Denial of Service | precompute.py infinite loop or excessive runtime | mitigate | CI workflow timeout limits: 15 minutes max. Canonical profile count is bounded (32 profiles). Scenario count is bounded (3-5 initial). OpenFisca-France computation is CPU-bound but deterministic per profile — no infinite loop risk. |
| T-02-09 | Elevation of Privilege | PyPI supply chain (openfisca-france) | accept | openfisca-france is a widely-used package in the French gov ecosystem (AGPL). Version pinned in pyproject.toml. Risk accepted for development-time-only dependency — not deployed to production. |
| T-02-10 | Tampering | Scenario results falsification (e.g., manually edited JSON to show favorable results) | mitigate | Scenario data is regenerated by CI pipeline on every openfisca-france update. CI gate verifies version consistency. Human audit of committed JSON is possible (indent=2, human-readable). The `reform_patch` parameters are explicit — any citizen can verify the reform definition against the candidate's published program. |
