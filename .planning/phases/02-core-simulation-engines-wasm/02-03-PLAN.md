<objective>
Design and implement the parameter tree loading system — the Rust-side equivalent of OpenFisca's parameter resolution. Tax rule parameters (rates, brackets, thresholds) are loaded from Phase 1's `parameters-v2025.1.json` into a typed `Parameters` struct with date-based `BTreeMap` lookups following OpenFisca's "closest past date" semantics.

Purpose: The micro engine needs typed, version-validated access to all tax parameters (IR barème brackets, TVA rates, cotisation thresholds, aide amounts). TDD ensures date resolution edge cases (parameter changes on Jan 1, mid-year reforms, PLF updates) are correct before formulas execute.

Output: Fully tested Parameters struct with date-based lookup, version validation, and parameter value enumeration.

<interfaces>
The Phase 1 `parameters-v2025.1.json` has a known schema from the OpenFisca-compatible YAML rules. Each parameter file produces a JSON structure like:

```json
{
  "version": "rules-v2025.1",
  "parameters": {
    "ir.bareme": {
      "description": "Barème de l'impôt sur le revenu",
      "brackets": [
        {"threshold": 0, "rate": 0.0},
        {"threshold": 11294, "rate": 0.11},
        {"threshold": 28797, "rate": 0.30},
        {"threshold": 82341, "rate": 0.41},
        {"threshold": 177106, "rate": 0.45}
      ],
      "metadata": {"reference": "https://www.legifrance.gouv.fr/codes/article_lc/LEGIARTI000049647807", "unit": "EUR"}
    },
    "tva.taux": {
      "description": "Taux de TVA",
      "values": {
        "normal": {"value": 0.20, "metadata": {"reference": "..."}},
        "reduit": {"value": 0.055, "metadata": {"reference": "..."}},
        "super_reduit": {"value": 0.021, "metadata": {"reference": "..."}}
      }
    }
  }
}
```

The Rust Parameters struct must support:
- `Parameters::load_from_json(json: &str) -> Result<Self, LoadError>` — deserialize and validate
- `Parameters::version(&self) -> &str` — returns "rules-v2025.1"
- `Parameters::get_brackets(&self, key: &str) -> Result<&[Bracket], LoadError>` — for progressive taxation
- `Parameters::get_scalar(&self, key: &str) -> Result<f64, LoadError>` — for flat rates/amounts

Date-based resolution (D-08 match on period): For parameters with temporal variants, use `BTreeMap<NaiveDate, Value>` where lookup returns the value for the closest past date. The initial implementation handles the 2025 reference year; date resolution is extended by the code generator (D-08).

From RESEARCH.md line 549: "Date resolution logic (closest past date) is subtle; OpenFisca has well-defined parameter update semantics"
