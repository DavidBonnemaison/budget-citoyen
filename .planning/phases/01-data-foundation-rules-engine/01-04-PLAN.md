<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| openfisca-france package -> validation results | Reference values depend on correct openfisca-france version — pinned in pyproject.toml |
| CI runner -> output artifacts | CI gates validated JSON before Phase 2 consumption — prevents corrupted artifacts from propagating |
| GitHub Actions -> runner | Third-party CI runner — mitigated by content hash verification, no secrets in repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | CI — version check bypass | mitigate | Version consistency check is a hard CI gate (not advisory). grep for non-2025 date keys fails the build. Pattern: grep -r "20[0-9][0-9]-" packages/tax-rules/parameters/ | grep -v 2025 must return empty. |
| T-04-02 | Tampering | CI — artifact swap | mitigate | SHA-256 hash embedded in meta.json compared against computed hash at CI time. Mismatch = hard failure. |
| T-04-03 | Repudiation | Validation results | mitigate | All validation output includes openfisca-france version, reference year, and ISO timestamp. Results are reproducible — same profile + same openfisca-france version = same output. |
| T-04-04 | Information Disclosure | CI logs — real data paths | mitigate | CI uses synthetic/placeholder data only. Real data paths are environment variables, never hardcoded. Test files use small in-memory DataFrames — no file I/O to real data directories. |
</threat_model>
